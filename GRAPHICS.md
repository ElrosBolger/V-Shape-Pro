# V-SHAPE · Original graphics installation

## Source and recovery

Originals: `V-SHAPE-pacchetto-installazione.zip` supplied by the owner.
The supplied `icon-192.png`, `icon-512.png` and `splash-1080x2400.jpg`
are installed byte-for-byte. No generated or redrawn artwork is used.
The maskable PNGs, favicon and Apple touch icon are resized copies of
`icon-original.jpg`. Maskable files add only an opaque black safety margin;
the full original square fits within the central circle of radius 40%.

Recovery branch: `restore/vshape-before-original-graphics-20261116`.
Pre-change commit: `301916c161ce3d19e83978447b0aeb4e7b4c269b`.

## Launch behavior

The manifest retains the existing app identity, URL, scope, standalone mode,
and Home short name `V-SHAPE`. Native Android launch UI is generated by
Android/Chrome from manifest information; the website cannot replace it
with the full character artwork.

The separate HTML introduction uses the supplied portrait artwork on black,
with `object-fit: contain`. It never crops or stretches the image and adds
no border. The purple outline inside the original artwork is preserved.
A 1100 ms independent deadline starts a 220 ms fade, with removal by 1340 ms.
A CSS deadline provides a further visibility fallback. Reduced motion removes
the transition. Failed or late images do not cover the interface.

The introduction is skipped for an active saved workout, OAuth callbacks,
history restoration, hidden pages or inaccessible/invalid saved state.
It closes immediately on interaction, page hiding, or BFCache restoration.
The new launch code never writes localStorage or sessionStorage.

## Data and behavior preserved

Workout data stays in `localStorage` under `vshape_final_v1`.
Spotify storage, PKCE/OAuth, refresh, and player code are unchanged.
The eight-week program and backup formats are unchanged.
One pre-existing rest-view issue found during browser testing is guarded:
when the clock element is absent, its DOM updater stops, retaining the
absolute saved rest deadline for subsequent resumption.

The service worker precaches all artwork, leaves Spotify requests alone,
never caches OAuth query strings, and removes only obsolete V-SHAPE caches.
It does not delete workout data or other applications' caches.

## Verification

Run the dependency-free checks with:

```sh
node --test tests/graphics.cjs
```

34 isolated tests passed: launch timing and skip/error paths, reduced motion,
cache install/update/offline behavior, rest-screen navigation/resumption,
and JSON/CSV backup functions with synthetic data.

Both inline scripts and the worker passed `node --check`; manifest JSON,
local asset paths, dimensions, safe circles and unchanged application source
(except the clock guard) were checked. The obsolete SVG is removed.

Local Chrome checks used synthetic data only: week selection, workout start,
set entry, saved timer resumption after reload, menu navigation, JSON download
and import, diary and progression display, and the unauthenticated music page.
The observed normal introduction was removed about 1.38 s after navigation.
A deliberately missing image removed the overlay within about 41 ms while
the app remained usable. Layouts were inspected at 432×960, 360×800 and
960×432 CSS pixels. Home icon previews used 48, 72 and 96 pixels and circle masks.
No application console errors remained in the tested normal flows after the
clock guard. Intentional missing-image testing produces its expected 404.

Physical Pixel/Android installation and authenticated Spotify Premium playback
were not available for testing. Existing installed icons can update later than
the site; preserve a JSON backup before considering removal/reinstallation.
Do not clear Chrome/site storage to refresh the graphics.
